# Linux appearance and startup behaviour

## Changed

- Linux: the light and dark mode can be chosen with any theme. Windows and macOS still leave that to the system setting, because their native styles read it themselves.

## Fixed

- Linux: packages rendered without their widget style, SVG icons and TLS backend, because the app looked for Qt plugins beside its own executable instead of the ones the system ships.
- The automatic test that runs when a subscription opens waited only for the core to answer, which happens before the tunnel's routes exist, so with Tun active the whole server list was reported as unavailable. It now waits for the tunnel.
- Linux: subscription requests carried no hardware id, computer name or username at all, because those were read the way only Windows provides them.
- The username switch for subscription requests had no effect of its own: it was tied to the computer name switch.
- Startup work held back by Tun authorization, such as the subscription update on start, was cancelled for the rest of the session instead of waiting, so a restart after an update never refreshed the subscriptions. It now runs once Tun becomes available, or once the mode is turned off.
- `Add from QR Code on Screen` was missing from the menu even though the reader shipped in every build, and its absence logged a warning on every start.
